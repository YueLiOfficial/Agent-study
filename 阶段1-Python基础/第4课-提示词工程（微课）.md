## 一、Prompt 是什么（30 秒建立心智模型）

- **Prompt = 你写给模型的需求文档**。
- 模型 = 一个**认真但死板的实习生**：你写得越清楚，它干得越准；你写得模糊，它就自己猜。
- **你已经写过 Prompt 了**——chat3/chat4 里那句 `system: "你是一个友好的 AI 助手"` 就是最基础的 Prompt（角色设定）。
- 所以这节微课不是学新东西，是把"你已经在做的事"变成**系统方法论**。

## 二、5 大技巧速览

| # | 技巧            | 一句话          | 什么时候用          |
| - | ------------- | ------------ | -------------- |
| 1 | 角色设定 Role     | 给模型身份和规则     | 问答、对话          |
| 2 | 指令清晰 Specific | 给格式、字数、边界    | 一切场景           |
| 3 | Few-shot 示例   | 给输入输出对，让它照着学 | 分类、格式模仿        |
| 4 | 思维链 CoT       | 让它一步步推理再回答   | 数学、逻辑、多步任务     |
| 5 | 结构化输出 JSON    | 要机器可读的格式     | **程序集成（工程必备）** |

## 三、实测脚本：prompt_test.py（5 组对比）

```python
import ollama

client = ollama.Client(host="http://localhost:11434")

def ask(system, user):
    """带 system 的提问（system 可为空字符串）"""
    resp = client.chat(
        model="qwen3.5:4b",
        messages=[
            {"role": "system", "content": system},
            {"role": "user", "content": user},
        ],
        stream=False,
    )
    return resp.message.content

# ① 角色设定对比
print("=== ① 角色设定 ===")
print("[无角色]", ask("", "设备报警 E-102 是什么意思？")[:80])
print("[维修专家]", ask("你是拥有20年经验的工业设备维修专家，回答专业、简洁、先给结论。",
                        "设备报警 E-102 是什么意思？")[:80])

# ② 指令清晰对比
print("\n=== ② 指令清晰 ===")
print("[模糊]", ask("", "解释一下PLC")[:80])
print("[清晰]", ask("", "用不超过100字，面向一线维修工，解释什么是PLC，并列出最常见的3个故障点。")[:80])

# ③ Few-shot（分类）
print("\n=== ③ Few-shot 分类 ===")
fewshot = """把下列句子分类为「故障报修/咨询/无关」三类。
例子1：变频器报警过流 → 故障报修
例子2：这款型号支持485通讯吗？ → 咨询
例子3：今天天气不错 → 无关
现在分类：触摸屏开机黑屏"""
print(ask("", fewshot))

# ④ CoT（思维链）
print("\n=== ④ CoT ===")
print("[直接答]", ask("", "进水管3小时灌满水池，出水管6小时放空，同时开，多久灌满？")[:100])
print("[一步步想]", ask("", "进水管3小时灌满水池，出水管6小时放空，同时开，多久灌满？请先列出计算步骤，再给出答案。")[:100])

# ⑤ 结构化输出（JSON）
print("\n=== ⑤ 结构化输出 ===")
js = ask("只输出JSON，不要任何解释和多余文字。",
         '请分析：设备="伺服电机"，现象="运行中异响"。输出：{"设备": "...", "可能原因": ["...", "..."], "建议": "..."}')
print(js)
import json
try:
    data = json.loads(js)          # 能解析成功 = 程序可直接对接
    print("\n✅ json.loads 解析成功，字段：", list(data.keys()))
except Exception as e:
    print("\n❌ 解析失败（模型带了多余文字）：", e)
```

## 四、技巧详解（重点看对比实验的效果）

### 1. 角色设定（Role）

给模型一个身份，它会自动调整语气、深度、知识组织方式。  
关键：**system 里写身份 + 规则**，不要写在每句 user 问题里。

### 2. 指令清晰（Specific）

模糊指令 → 模型自己猜需求，输出飘。  
好指令三要素：**目标 + 约束（字数/格式）+ 边界（面向谁）**。

### 3. Few-shot（示例）

模型本质是**模式匹配机器**——给 2~3 个输入输出对，比解释一百句都管用。  
适用：分类、抽取、格式模仿（前面 chat 里的 role 结构也是这个道理）。

### 4. CoT（思维链）

直接答复杂问题容易错；加一句"请一步步推理"，准确率显著提升。  
注意：deepseek-r1 这类推理模型天生会思考；普通模型（qwen3.5 非思考模式）需要你引导。

### 5. 结构化输出（JSON）——工程必备

**为什么重要**：模型输出文字飘忽，但程序要的是**机器可读数据**。  
`只输出 JSON` + 给格式模板 → `json.loads` 直接解析 → 类比 C++ 里反序列化接口（protobuf / JSON parse）。  
注意坑：小模型偶尔输出多余文字，用 system 强约束 + 必要时正则兜底。

## 五、心法总结（贴墙上）

1. **具体 > 抽象**：给数字、给格式、给例子，别给感觉
2. **给格式 > 给描述**：直接告诉它"用 JSON，字段是 XXX"
3. **示例 > 解释**：模型是模式匹配机器
4. **说清"不要做什么"**：边界写出来，防止跑偏
5. **输出要机器可读**：能 json.loads 的 prompt 才是好 prompt
6. **Prompt 是调出来的**：一次不行就 refine，迭代是最正常的工作方式
