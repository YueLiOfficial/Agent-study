## 一、先懂一个核心概念：LLM 是无状态的

- LLM 本质是一个「**无状态函数**」：输入一段文字（messages），输出一段文字。
- 它**不记得**任何历史对话——多轮对话能聊下去，是因为我们把历史消息**一起传回去**。
- 所以 API 请求里的 `messages` 是一个列表，长这样：

```python
messages = [
    {"role": "system",    "content": "你是一个工业设备维修助手"},  # 设定人格（可选）
    {"role": "user",      "content": "设备报警 E-102 是什么意思？"},
    {"role": "assistant", "content": "E-102 表示电机过载……"},       # 模型上次的回答
    {"role": "user",      "content": "那要怎么处理？"},               # 当前问题
]
```

**role 只有三种**：`system`（设定人格/规则）、`user`（用户说的话）、`assistant`（模型说的话）。
记住这个模型，后面 RAG、Agent 全都在操作这条消息流。

## 七、第 2 步：流式输出（chat2.py）

> 用户模型：qwen3.5:4b（若模型开了思考模式，回答前可能先输出思考过程；本讲义最初用 deepseek-r1 时该现象较明显）。
> 目标：让回答一个字一个字蹦出来（打字机效果），这是聊天体验的关键。

### 1. 核心：两个 stream 开关，别搞混

| 开关 | 作用 | C++ 类比 |
|---|---|---|
| body 里 `"stream": true` | 告诉 Ollama：**边生成边发送**，别憋到最后 | 服务器端 chunked 传输 |
| `requests.post(..., stream=True)` | 告诉 requests：**边收边读**，别等全量收完 | 逐块读 socket 缓冲 |

只开第一个、不开第二个，可能还是等全量；两个都开才是真流式。

### 2. 流式返回长什么样（NDJSON：每行一个独立 JSON）

```json
{"model":"qwen3.5:4b","message":{"role":"assistant","content":"我"},"done":false}
{"model":"qwen3.5:4b","message":{"role":"assistant","content":"是"},"done":false}
{"model":"qwen3.5:4b","message":{"role":"assistant","content":"DeepSeek..."},"done":false}
{"model":"qwen3.5:4b","message":{"role":"assistant","content":""},"done":true}
```

每行的 `message.content` 是**一小段**文字，拼起来就是完整回答；最后一行 `done: true`。

### 3. chat2.py 完整代码

```python
import requests
import json

resp = requests.post(
    "http://localhost:11434/api/chat",
    json={
        "model": "qwen3.5:4b",
        "messages": [{"role": "user", "content": "用三句话介绍你自己"}],
        "stream": True,          # ① 告诉 Ollama：流式生成
    },
    stream=True,                 # ② 告诉 requests：边收边读
)

for line in resp.iter_lines():            # 逐行读响应（类比逐行读 socket 缓冲）
    if not line:                          # 跳过空行
        continue
    chunk = json.loads(line)              # 每行都是独立 JSON，单独解析
    content = chunk["message"]["content"] # 取这一小段文字
    print(content, end="", flush=True)    # 不换行 + 立即刷新 → 打字机效果
    if chunk.get("done"):                 # 最后一块的标志
        print()                           # 收尾换行
```

### 4. 逐行要点

- `iter_lines()`：流式响应的逐行迭代器，服务器发一行我们处理一行
- `json.loads(line)`：把一行 JSON 文本解析成字典（类比 nlohmann::json::parse）
- `print(x, end="", flush=True)`：`end=""` 取消默认换行；`flush=True` 强制立即输出（类比 `cout << x << flush`），不加会攒在缓冲区不显示
- `chunk.get("done")`：`.get()` 取不到键时返回 None（安全），最后一块标记

### 5. 推理模型的特殊之处（原 deepseek-r1 的现象，Qwen 视模式而定）

推理模型（如 deepseek-r1）正式回答前会先输出一大段「思考过程」（可能带 `<think>` 标签或单独字段）。流式时你会先看到它"想"再看到它"答"——不是乱码，这是它的内心戏。Qwen3.5 若开启思考模式也可能有类似输出，若未开启则直接回答。

## 八、第 3 步：多轮对话（chat3.py）

> 目标：让机器人"记得"聊过什么——把历史消息攒成一个列表，每轮全量发回去。

### 1. 原理回顾（第 1 步讲过，现在用起来）

LLM 无状态 → **messages 列表就是它的"记忆"**。每轮对话做 3 件事：

```
1. 用户输入 → append 进 messages（记下来）
2. 把【整个 messages】发给模型（历史全带上）
3. 模型回答 → append 进 messages（也不能忘）
```

assistant 的回答**必须也存回去**——否则下一轮模型不知道它自己说过什么。

### 2. chat3.py 完整代码

```python
import requests
import json

# ① 记忆容器：以 system 人格开头，之后每轮追加
messages = [
    {"role": "system", "content": "你是一个友好的 AI 助手，回答尽量简洁。"},
]

def chat(user_input):
    """把用户输入加进历史，调用模型，返回完整回答"""
    messages.append({"role": "user", "content": user_input})  # 记下用户问题

    resp = requests.post(
        "http://localhost:11434/api/chat",
        json={
            "model": "qwen3.5:4b",
            "messages": messages,     # ② 把【全部历史】发过去
            "stream": True,
        },
        stream=True,
    )

    reply = ""                        # ③ 攒流式小块的容器
    for line in resp.iter_lines():
        if not line:
            continue
        chunk = json.loads(line)
        piece = chunk["message"]["content"]
        print(piece, end="", flush=True)  # 打字机效果
        reply += piece                # ④ 同时拼成完整回答
        if chunk.get("done"):
            break

    messages.append({"role": "assistant", "content": reply})  # ⑤ 记下模型回答
    print()
    return reply

# ⑥ 主循环：一直聊，输入 exit / quit / 拜拜 退出
while True:
    user_input = input("\n你：").strip()
    if user_input.lower() in ("exit", "quit", "拜拜", "退出"):
        print("再见！")
        break
    if not user_input:
        continue
    print("AI：", end="")
    chat(user_input)
```

### 3. 新知识点逐个看

| 代码 | 说明 | C++ 类比 |
|---|---|---|
| `def chat(user_input):` | 第一次在项目里用函数封装，一处写、反复调 | `void chat(const string& input)` |
| `messages.append({...})` | 往列表尾部加一条消息 | `vec.push_back(...)` |
| `reply += piece` | 把流式小段拼成完整回答（存历史用） | `str += piece` |
| `input("\n你：")` | 从键盘读一行（返回字符串） | `cin >> s`（更宽松） |
| `.strip()` | 去掉首尾空白 | `boost::trim` |
| `user_input.lower()` | 转小写，方便匹配 exit/quit | `tolower` 转换 |
| `while True:` + `break` | 无限循环，条件满足才跳出 | `while(1)` + `break` |

### 4. 推理模型补充：思考过程要不要存进历史？

如果模型输出了 `<think>...</think>` 思考过程（推理模型常见），**存历史前建议先滤掉**——不然历史又长又乱还费 token：

```python
import re
reply = re.sub(r"<think>.*?</think>", "", reply, flags=re.DOTALL)  # 去掉思考过程
```

### 5. 埋个伏笔（后面会用到）

messages 越攒越长，**总有过上下文窗口装不下的一天**——这正是后面 RAG（模块 5）要解决的核心问题之一：模型记不住全部资料，我们就检索出最相关的片段塞给它。现在先记住这个痛点。

## 九、第 4 步：Streamlit 界面（chat4.py）

> 目标：把命令行聊天机器人升级成网页聊天界面（浏览器里用）。
> Streamlit 是 Python 里最省事的网页框架——你写 Python，它帮你生成网页。

### 1. 先懂 Streamlit 的运行机制（最重要的概念）

**Streamlit 每次交互（点按钮、输入文字）都会把整个脚本从头到尾重跑一遍。**

- 普通变量（`messages = [...]`）：每次重跑都重新创建 → **聊两句就失忆**
- `st.session_state`：Streamlit 提供的**跨重跑持久存储**（像字典一样用）→ **真正的记忆**

所以聊天记录必须放 `st.session_state.messages`，不能放普通变量。这是新手必踩的坑。

C++ 类比：脚本重跑 ≈ 每次事件处理函数被调用；`st.session_state` ≈ 成员变量/static 变量（函数调用之间保留）。

### 2. chat4.py 完整代码

```python
import requests
import json
import streamlit as st

# ① 聊天记录放 session_state（跨重跑保留，相当于网页版"记忆"）
if "messages" not in st.session_state:
    st.session_state.messages = [
        {"role": "system", "content": "你是一个友好的 AI 助手，回答尽量简洁。"},
    ]

st.title("我的第一个 AI 聊天机器人")      # 页面标题

# ② 把历史消息渲染成气泡（system 不显示）
for msg in st.session_state.messages:
    if msg["role"] == "system":
        continue
    with st.chat_message(msg["role"]):   # 用户靠左、AI 靠右的气泡
        st.write(msg["content"])

# ③ 输入框：用户输入后，脚本自动重跑
prompt = st.chat_input("说点什么吧……")
if prompt:
    st.session_state.messages.append({"role": "user", "content": prompt})
    with st.chat_message("user"):
        st.write(prompt)

    # ④ 调用本地模型（流式，和 chat3 一样）
    resp = requests.post(
        "http://localhost:11434/api/chat",
        json={
            "model": "qwen3.5:4b",
            "messages": st.session_state.messages,
            "stream": True,
        },
        stream=True,
    )

    with st.chat_message("assistant"):
        box = st.empty()               # ⑤ 占位符：可以反复刷新内容
        reply = ""
        for line in resp.iter_lines():
            if not line:
                continue
            chunk = json.loads(line)
            piece = chunk["message"]["content"]
            reply += piece
            box.write(reply)           # ⑥ 每次更新 → 打字机效果
            if chunk.get("done"):
                break
        st.session_state.messages.append({"role": "assistant", "content": reply})
```

## 十、第 5 步：FastAPI 服务化（chat_api.py）

> 目标：把聊天机器人包装成一个 HTTP API（POST /chat），任何客户端都能调用——包括你未来的 Qt 应用。
> 这是里程碑 1 的最后一步，做完它，你的第一个简历项目就完整了。

### 1. 架构升级：现在的系统多了一层"服务"

```
任何客户端（curl / 浏览器 / 未来的 Qt 应用）
        ⇓ POST /chat（带 JSON：messages）
   FastAPI 服务（chat_api.py，端口 8000）
        ⇓ 转发给 Ollama
   Ollama → qwen3.5:4b → 回答 JSON 原路返回
```

**关键设计：API 是无状态的**——聊天历史由客户端自己维护，每次调用把 messages 全量传过来。这和"LLM 无状态"是同一套哲学，也为 Qt 客户端将来自己管理对话状态铺好了路。

### 2. 安装与运行

```bash
pip install fastapi uvicorn          # 装库（一次性）
uvicorn chat_api:app --reload       # 启动服务 → http://localhost:8000
```

启动后浏览器打开 **http://localhost:8000/docs** —— FastAPI 自动生成的接口文档，可以直接在网页里"试运行"接口，这就是后端开发者的快乐。

### 3. chat_api.py 完整代码

```python
from fastapi import FastAPI          # Web 框架：你写函数，它管 HTTP
from pydantic import BaseModel       # 请求体校验：定义客户端发什么
import requests
import json

app = FastAPI(title="聊天机器人 API") # 创建服务实例

# ① 请求体模型：声明客户端 POST 过来的 JSON 结构
class ChatRequest(BaseModel):
    messages: list                   # 客户端把对话历史全传过来

# ② 一个函数 = 一个接口：装饰器声明路径和方法
@app.post("/chat")
def chat(req: ChatRequest):
    # ③ 转发给本地 Ollama（就是 chat1 里那套，复用！）
    resp = requests.post(
        "http://localhost:11434/api/chat",
        json={
            "model": "qwen3.5:4b",
            "messages": req.messages,
            "stream": False,         # API 先用非流式，简单
        },
    )
    answer = resp.json()["message"]["content"]
    return {"reply": answer}         # ④ 返回 JSON 给客户端
```

### 5. 新知识点

| 代码 | 说明 | C++ 类比 |
|---|---|---|

### 8. 补充：用户实际方案（ollama SDK）+ 流式升级

#### A. ollama SDK 版（比裸 requests 更简洁，用户实际采用）

```python
from fastapi import FastAPI
import ollama
from pydantic import BaseModel

client = ollama.Client(host="http://localhost:11434")   # 官方 SDK 客户端

app = FastAPI(title="聊天机器人 API")

class ChatRequest(BaseModel):
    messages: list

@app.post("/chat")
def chat(req: ChatRequest):
    reply = client.chat(
        model="qwen3.5:4b",
        messages=req.messages,
        stream=False,
    )
    return reply.message.content     # 非流式返回完整对象，.message.content 取回答
```

说明：SDK 底层调用的还是同一个 HTTP API，只是把 JSON 解析、连接管理封装好了。两种方案等价，SDK 更短更不易错。

#### B. 流式升级：两层流式

- **第一层（Ollama SDK）**：`client.chat(..., stream=True)` 返回**生成器**，逐块得到内容
- **第二层（FastAPI）**：`StreamingResponse` 把生成器的内容**边产生边发给客户端**

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
import ollama
from pydantic import BaseModel

client = ollama.Client(host="http://localhost:11434")
app = FastAPI(title="聊天机器人 API")

class ChatRequest(BaseModel):
    messages: list

@app.post("/chat")
def chat(req: ChatRequest):
    def generate():                          # 含 yield 的函数 = 生成器（闭包，能访问 req）
        stream = client.chat(
            model="qwen3.5:4b",
            messages=req.messages,
            stream=True,                     # ① SDK 层流式：返回生成器
        )
        for chunk in stream:                 # 每个 chunk 是 dict
            yield chunk["message"]["content"]  # ② 逐块吐给 FastAPI

    return StreamingResponse(generate(), media_type="text/plain")  # ③ 边生成边发给客户端
```

#### C. 客户端怎么接收流式响应

```python
import requests
resp = requests.post(
    "http://localhost:8000/chat",
    json={"messages": [{"role": "user", "content": "你好"}]},
    stream=True,                             # 客户端也要开流式
)
for line in resp.iter_lines():
    print(line.decode("utf-8"), end="", flush=True)
```

注意：流式后响应从「JSON 对象」变成「纯文本流」，客户端接收方式随之改变。
